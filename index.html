生产日志

    交接文档（开发说明 · 完整版）

    本页为单文件静态构建（index.html + assets/three.min.js），交接文档就内嵌在本节，不依赖任何外部文件。源码顶部另有架构总览注释，与本节内容一致。

    架构
    用户输入（控制条 / 调度台 / 点选）只写「意图字段」→ [M1 仿真内核] step(dtMin) 推进状态 S / stations / lines / ledger，并提供只读派生 stationStatus() / lineStatus() / bottleneck() / oee() → [M2 场景层 + M3 设备层] updateScene() 读状态驱动动画与灯色；[M4 相机层] 以 desiredPos/Tgt 经阻尼 / 碰撞 / 遮挡淡出得到实际机位；[M0 CONFIG] 是所有模块共读的唯一参数源。部署结构为 index.html + assets/three.min.js，业务代码集中在 index.html，故模块边界用分节横幅 [M0]…[M5] + 命名约定实现，拆多文件时保持同样编号与职责。
    模块职责
    M0 配置（CONFIG / STATUS / STATUS_COLORS）· M1 内核（S、stations、lines、ledger、step）· M2 场景（buildShell / buildUpstream / buildAsepticZone / buildUtilities / buildCipStation / buildQcLab / buildWarehouseDock / buildPeopleLogistics / buildSafety / buildSignage、updateScene（含动画 LOD）、注册表 D）· M3 设备（buildLine + 共享部件工厂）· M4 相机（flyTo / goPreset / buildTour + TOUR_STOPS 解说点 / updateCamera）· M5 UI（renderKpis / renderInfo / drawChart / scenarios）· 性能横切在主循环 loop（帧率采样与自适应降级）
    数据流（拉式生产）
    装箱出瓶 → Line.capQ → Line.queue → 杀菌 queue（向在线无故障产线均分）→ 调配 queue → 原料供应注入。顺序写在 step() 注释里，不要打乱。
    能耗口径（V6 三分账）
    水 / 电 / 蒸汽分开计量、分开计价：账本字段 waterM3（m³）/ powerKwh（kWh）/ steamKg（kg），单价在 CONFIG.utilities（pricePerM3 / pricePerKwh / pricePerKg），利润成本 = 原料 + 三项公用工程费（utilCost）+ 固定 + 换型费。消耗来源三处，全部经 chargeUtilities(L, 水, 电, 蒸汽) 入账：① 生产流量（totalFlow × 各自 perFlow）；② CIP 事件（utilities.cipEvent，触发时计入当前产品）；③ 换产事件（utilities.changeoverEvent，计入新产品，与换型费同口径）。旧版单一 energyKwh 按电价折算的口径已废除，文档与界面不得再出现。
    扩容轮（厂房放大 + 灌装/无菌罐做大 + 各区细化）
    体量参数全在 CONFIG：factory（floorW/floorD/wallH/roofY，地面/墙/屋顶/立柱/阴影/遮挡顶板派生）、lineSpacing=36（线间距放开）、fillerHeads=36 / fillerRadius=4.4（旋转灌装一体机：冲瓶转盘→36 头大转盘→封盖转塔，整圈加高防护罩 + 大料缸 + 粗进料总管）、asepticCount=5 / asepticRadius=4.8 / asepticHeight=16 / asepticCapacityM3=105（容量由旧版 38 m³ 按体积比派生，铭牌与信息卡读 CONFIG，勿写死）、sterilizerTubes=8。各区新增功能件：原料卸料泵台+暂存称量罐+分路阀组、检重剔除段、装箱前积放台、分拣复核工位、缠绕膜机、第三月台位+伸缩装车带、分汽缸、空压后处理过滤组、CIP 回收罐、留样冷藏柜。机位 PRESETS 新增 blending（调配特写）/ packaging，overview/aseptic 等已按新布局重标；碰撞盒与遮挡顶板同步放大。
    调配工艺模型（配方 + 批次状态机）
    数据：CONFIG.recipes[产品id] = { name, batchL, mixMinutes, note, ingredients[{name, amount, unit, source, from}] }；CONFIG.blendProcess = { sugarTempC（溶糖热水约 80℃）, stages[八阶段：water→syrup→conc→minor→topup→mix→sample→discharge，各带 dur/source/color] }。改配方/时长只改这两处。阶段序列由 activeStages() 按配方实际用料过滤（矿泉水无糖浆/浓缩液阶段自动跳过）；mix 阶段时长取配方 mixMinutes。状态机 BP{idx,left,batch} 在 step() 中随生产推进（暂停/换型冻结），渲染与批次卡只读 BP/curBlendStage()/ingredientStatus()。罐位分工（buildUpstream）：(-58,-18) 水处理缓冲 / (-58,18) 浓缩液 / (-34,-18) 糖浆暂存 / (-34,18) 主调配 / (-46,30) 溶糖 / (-14,-18) 待杀菌缓冲；每来源一条独立管进主罐，D.blendFlow[source] 注册管路材质/阀门（编号 BLEND_VALVES：V1 水/V2 糖浆/V3 浓缩/V4 小料/V5 出料）/泵灯，updateScene 按阶段驱动：当前管按物料色脉冲流动、阀门进度 8% 后开（先关后开）、来源泵灯亮、来源罐液位回落、主罐液位涨落、搅拌阶段液色由浑浊渐变成品色。点任一调配罐（kind:"blendTank"，pickAt 优先命中）出批次卡，含配方、用料状态、搅拌剩余与管路颜色图例。
    布局放大轮（间距再放一档 + 前进/后退可最小化）
    布局参数入口 = CONFIG.layout（hallW/hallD 厅内墙跨 300×116、chainZ/preheatX/homogenizerX/homogenizerZ/sterilizerSkidX/coolingX 杀菌链坐标、asepticTankX0/asepticTankSpacing/asepticTankZ 无菌罐排、rackX 货架列、dockBays 月台车位）+ CONFIG.factory（360×230、层高 15/屋顶 24）+ CONFIG.lineSpacing=40。杀菌链现为：预热 (-54,8) → 均质 (-32,22，偏南错开) → 管式杀菌机组 (-6,8) → UHT 柜机 (-25,-14，buildUpstream 内 uht 组整体偏移 -10,-14) → 冷却 (20,8) → 无菌罐排 (x -58..18 / z -30，罐距 19) → 灌装总管 (x=4)；机组间以长管段相连（pIn/pMid/pUp/pFeed 在 buildAsepticZone，长度即间距的视觉证据），锅炉蒸汽总管改接 x=-25。调配罐距 24×36、货架列距 16（巷道 ≈13）、月台车距 30、复核/缠膜工位西移到 x=74/73。联动项（改布局后必须同步核对）：PRESETS 全部机位、buildTour 路点/目标、COLLIDERS 碰撞盒、遮挡顶板 slab 与 inside 判定、工人 w1/w3 路线与人行通道 (z=-42)、叉车 1 矩形路线 (x 76/124)、buildSignage 铭牌/立牌坐标、UHT 蒸汽粒子原点 (-25,12,-14)。灌装线内部工位（冲瓶→灌装→封盖→贴标→检重→膜包→装箱）是连续输送带工艺、本就不留间隙，间距体现在线间 (40) 与线前后缓冲段。前进/后退最小化：控制条内 #moveCluster（#moveToggle 切换钮 + #moveBtns），收起态给 #controlBar 加 .move-collapsed 类隐藏按钮组与 .ops-hint，只剩一颗「🧭 移动」钮；默认小屏 (<900px) 收起、大屏展开，会话内选择不持久化；逻辑在 bindMoveControls 的 setMoveCollapsed（window.__setMoveCollapsed 可调试切换），收起时自动清 moveDir。
    巡游解说改法
    文案集中在 M4 的 TOUR_STOPS（u=曲线位置 0~1、dwell=停留秒数、title/text）。改文案只改该数组；改路线改 buildTour 的 pts/tgts 并同步核对 u 顺序。停留/触发逻辑在 updateCamera，字幕 DOM 是 #tourCap，跳过/退出按钮在 M5 绑定。
    性能开关位置
    预算全在 CONFIG.perf：像素比上限（桌面/移动）、LOD 距离与降频、降级阈值（阴影分级 R3 起在 CONFIG.light.shadowTiers，初始档桌面 high / 移动 R5 起为低端档 eco 512，参数组 CONFIG.perf.mobileLow）。移动端判定在 buildScene 内（isMobileGL / __perfTier）。真机读数在数据抽屉「真机性能」四格（R5）。帧率显示：顶栏「帧率」按钮，默认关，开启后读数写在按钮上；帧率持续低于阈值会自动逐级降质（像素比→关阴影，只降不升，逻辑在 loop 的 sampleFps）。瓶/箱/货架孔位/试剂瓶均为 InstancedMesh，勿改回逐个 Mesh。

    字体加载方案 = 异步加载 + 系统回退（非自托管）：Google Fonts 样式表改用 preload + onload 切 rel 异步引入（URL 带 display=swap），已移出加载关键路径；font-family 回退栈写清为 Noto Sans SC → PingFang SC / Hiragino Sans GB / Microsoft YaHei → system-ui，等宽为 JetBrains Mono → ui-monospace / SFMono / Menlo / Consolas。字体域名完全不可达时页面按系统字体直接渲染、数秒内可达 DOMContentLoaded，字体晚到只平滑替换字形；牌面 canvas 文字同样按该回退栈绘制。顶栏小屏布局：标题区 flex 可收缩、标题/副标题单行省略号截断，按钮组不收缩；≤900px 全面收紧内边距，≤560px 再收一档，≤420px 隐藏诊断用的「帧率」按钮（非关键按钮，≥421px 恢复）以保「数据」按钮与标题完整在视口内；底部控制条的分段控件（机位含「杀菌无菌区」、前进/后退、ops-hint）小屏允许换行、控制条仅纵向可滚且滚得到底，横向不溢出。建场时机：buildScene() 已移至 DOMContentLoaded 后经 rAF + setTimeout 异步执行（bootFactory，耗时打 console.info），建场期间显示「工厂搭建中…」加载态、建好自动移除，勿改回脚本尾部同步执行。

    ⚠ 本节记录的是旧实现，R6 起不再成立：当时隐藏入口 = 调度台标题栏的 #dispatchHideBtn（✕ 隐藏）与底部控制条末尾的 #controlHideBtn（✕ 隐藏控制台）；逻辑 = [M5] 调度台绑定旁的 setConsoleHidden，只切 body.console-hidden 一个类，CSS 据此把 #dispatch 与 #controlBar 一起淡出/滑出 + visibility:hidden + pointer-events:none（完全消失、不占位、不拦画布手势），样式段在 CSS 的「console overall hide」注释块。此「关联隐藏」正是 R6 用户点名修正的错误，现行口径一律以下方 R6 节为准。唤回 = 右下角浮钮 #consoleShowBtn（🎛 控制台，仅隐藏时可见可点），其状态点/文案 #consoleDot/#consoleStatus 由 renderKpis 按 S.running/changeover 同步（运行中绿点/换型中蓝点/已暂停黄点/待机灰点）。与既有两套折叠划清：调度台 .closed（只折 body）与移动组 .move-collapsed（只折前进/后退）都不被本功能触碰，所以恢复时各自回到隐藏前状态。默认显示面板；隐藏只在会话内有效（不持久化），除唤回钮外任何操作（切机位/巡游/开数据抽屉/场景按钮程序化点 playBtn）都不会清掉该类把面板弹回；隐藏不影响仿真 step 与已设参数。
    R1 工艺真实感（杀菌链动态 + 无菌守恒 + 灌装联动 + 批次衔接）
    参数入口：CONFIG.sterilizeProcess[产品id] = { uhtTempC / holdSec / preheatC / coolOutC / homogP1 / homogP2 / flowFactor }（茶 137℃/4s·150/30bar、橙汁 136℃/6s·200/50bar、可乐 133℃/4s·120/25bar、矿泉水 85℃/2s·80/15bar 量级），CONFIG.asepticStockCap=30000 / asepticStockInit=4500（瓶当量）。守恒链（step）：杀菌处理 sterMove = min(队列, 额定×flowFactor×dt, 罐容剩余) → ASEPTIC.stock 上升；灌装拉料 feedMove = min(stock, 产线队列空间, 灌装总需求×1.25) 按各线空间占比分配 → stock 下降；stock=0 时产线队列见底触发 lineStatus 饥饿「无菌罐待料」，罐满时杀菌 stationStatus 为 BLOCKED。totalWip() 已含 stock，换产 startChangeover 清 stock 并按在制品口径报废计入旧产品成本（与调配清线一致），applyProduct 时 STER_FEED 重置，杜绝旧产品换产后继续灌出。批次衔接：STER_FEED 在 advanceBlendBatch 出料完成时更新为该批 {num, productId}，sterBatchInfo() 在出料阶段显示当前出料批、其余显示 STER_FEED；杀菌区信息卡（kind:aseptic）、杀菌工位卡、调配批次卡三处同源显示。渲染：D.sterFlow 五段（preheat/homog/uht/cooling/aseptic，各自管路材质+段灯，料色语义与调配管路一致：流动=料色脉冲、停=暗灰、CIP/换型时 UHT/无菌段显清洗蓝）；STER_DYN 显示值（tempC/preheatC/coolOutC/homogP1/homogP2）由 updateScene 向工艺目标趋近（温度慢 k≈0.45/s、压力快），待机回落（运行热待机保工艺温、无料均质无压、CIP 82℃、故障 70℃、暂停向 48℃、未开工 28℃），动态参数牌 D.sterPlates（UHT/均质/预热-冷却，makeDynPlate 画布纹理、文本不变不重绘）与信息卡同读 STER_DYN；无菌罐液位柱 D.asepticLiquids 按 asepticPerTankFrac 顺序充填（不再随机正弦，原料罐视管仍正弦）。灌装联动：每线 dyn.feedPipeMat/feedLampMat/feedPumpMat/feedWheel（供料支管/阀灯/泵灯/阀手轮，buildLine 内建），开阀条件 = 运行+在线+无故障+stock>0.5+有瓶流；转速 rpm = 实际灌装速率（lastMove/lastDt）/800 驱动转盘/封盖塔/贴标辊/星轮（含冲瓶）/暂存转盘/输送带，停线故障即 0 同步停转；空瓶段（bx<0.5）瓶子仅在 flow>0.05 时显示，停线即断流，已灌段瓶子留带上（phase 冻结），产量计数仍走内核 produced 不受视觉瓶数影响。

    接口约定（内核 ↔ 渲染）

    • 渲染层只读 S / stations / lines 与状态函数返回值；禁止直接改 queue / ledger / 账本。
    • UI 写操作只有两类：改 S 意图字段（开停 / 参数 / 目标）、经 repairStation / repairLine 抢修（自动按 CONFIG.repairFee 计费）。
    • 产品颜色经 window.__setProductColor(hex) 单向通知渲染层（瓶体 / 液面 / 饰条），不要反向读产品数据。
    • CIP 站可视状态由 sterilize 工位的 cipLeft 与 S.changeover 派生（updateScene 内），CIP builder 不持有业务状态。
    • 公用工程入账只能走 chargeUtilities()（同时写全厂总量与产品账本），禁止在 step / 换产 / CIP 之外直接改 waterM3 / powerKwh / steamKg。

    已知限制

    • 单文件约 3100 行，ES5 风格（var / 函数）为兼容现有代码，接手重构时再统一到模块化构建，不要混写。
    • 巡游解说点 u：R5 前按路点序号手估、个别点可早/晚约 1 秒——R5 起由 alignTourStops() 按弧长表精确回填（误差 <0.2 秒），改路线后自动重算；自适应降级只降不升，但 R4 起已可手动恢复：降级时画面上方弹出提示条，点「恢复高画质」即回设备档基准（或控制台 window.__restoreQuality()），不必刷新页面。
    • 相机遮挡淡出基于材质级透明度，同一材质多处共用时会一起淡（罐体 / 货架 / 顶棚已按此设计）；北侧公用工程区建筑未纳入淡出清单，从北侧高位看厂内时需手动切顶棚。
    • 瓶子为实例化视觉流量，不与 queue 数值逐瓶对应；仓库箱数由 WH 入/出库守恒驱动（FIFO 窗口渲染）；工人为固定路线巡演，叉车/AGV/吊车由仓储活动门控待机，均不参与产能计算。
    • 移动端为可用级适配（面板折叠 / 点按拾取），未做专门的手势教程；低端机降级档已由 R5 补齐（CONFIG.perf.mobileLow：像素比 1.0 / 阴影 eco 512 / 粒子 0.3 / LOD 110，判定与恢复逻辑见交接文档 R5 节）。

    后续可扩展方向（V6 之后）

    • 多厂区：CONFIG 与内核已与渲染解耦，可按「一个内核实例 + 一个场景组」复制出二号厂区，账本按厂区前缀分开。
    • 真实数据接入：把 step() 的参数来源换成 MES/Excel 导入的班次数据即可（S 意图字段就是接入面），渲染层不用动；注意本页是静态构建，实时接口需另加后端。
    • 更细的公用工程：压缩空气、冷冻水可按 utilities 同构再加两项（字段 + perFlow + 单价 + chargeUtilities 扩展）。
